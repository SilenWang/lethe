# Lethe as an installed app (PWA)

Lethe ships a web app manifest and a service worker, so Chromium-based browsers
(Chrome / Edge) can install it and run it in its own window — no browser
chrome, and the shell keeps working from cache. The server-side data boundary
is unchanged: the browser still owns the user's data, and **the service worker
only ever caches the app's own static assets**.

## What was added

| File | Role |
|---|---|
| `lethe/web_static/manifest.webmanifest` | Name, icons, `display: standalone`, theme colour, `start_url: "/"`, `scope: "/"` |
| `lethe/web_static/sw.js` | Service worker: pre-caches the static shell, refreshes it in the background, drops old caches |
| `lethe/web_static/icons/icon-192.png`, `icon-512.png`, `icon-512-maskable.png` | Install/launcher icons (generated by `tools/make_pwa_icons.py`) |
| `app.py` | Serves `/manifest.webmanifest` and `/sw.js`, links the manifest in the page head, registers the worker |

## Install

1. Start Lethe (`pixi run lethe` / the launcher) and open it at
   `http://127.0.0.1:8731` (or `http://localhost:8731`).
   **Installation needs a secure context** — `localhost` counts; a plain
   LAN IP (`http://192.168.x.y:…`) does not, so install from the same machine.
2. Chrome/Edge shows an **Install** icon in the address bar ("Install Lethe…").
   The menu entry *Cast, save and share → Install page as app* works too.
3. Accept: the app opens in a standalone window (own taskbar/dock entry, no
   address bar) and gets a launcher icon. On first launch, the page asks for
   persistent storage so the browser is less likely to evict the dictionary and
   the re-identification mappings.

## What the service worker caches — and what it never touches

The worker's `fetch` handler answers **only** same-origin `GET` requests whose
path is on an explicit whitelist (`STATIC_PATHS` in `sw.js`):

```
/static/client-store.js   /static/migration.js      /static/favicon.svg
/static/fonts/cinzel-latin.woff2
/static/icons/icon-192.png  /static/icons/icon-512.png  /static/icons/icon-512-maskable.png
/manifest.webmanifest
```

Everything else goes straight to the network, untouched — the handler calls
`respondWith()` for nothing else:

- **Uploaded documents and their extracted text** (they travel over the NiceGUI
  WebSocket, so they never reach the worker at all);
- **De-identified / restored results** (downloaded from the page, never fetched
  through the worker);
- **The token → real mappings** (IndexedDB only, never a request);
- **`/api/migrate/*`** responses (POST, and already served with
  `Cache-Control: no-store`);
- **The page HTML** itself, which NiceGUI renders per session.

So the DevTools check is structural, not a promise: *Application → Cache
Storage* contains one cache named `lethe-static-…` holding exactly the static
files above — no document, no result, no mapping, no `/api/` entry.

## Updates and cache invalidation

- **App release:** `app.py` registers the worker as `/sw.js?v=<APP_VERSION>`.
  A new version means a new script URL, so the browser installs the new worker;
  `/sw.js` is served `Cache-Control: no-store`, so update checks always see the
  current bytes.
- **Cache name:** `lethe-static-v<APP_VERSION>-r<CACHE_VERSION>`. On activation
  the worker deletes every other `lethe-static-*` cache, so an upgrade can never
  serve a stale shell.
- **Asset changes without a version bump:** pre-caching uses
  `cache: 'reload'` (bypasses the HTTP cache) and the background revalidation
  uses `cache: 'no-cache'`, so a changed asset is picked up on the next load.
- **Rule changes:** bump `CACHE_VERSION` in `sw.js`.

## Verifying

- **Install / standalone window:** see above; the window has no address bar and
  the app appears under the OS app list.
- **Cache boundary:** DevTools → *Application → Cache Storage* shows only the
  whitelist; *Network* shows document uploads and `/api/migrate/*` never coming
  from the service worker (`Size` column shows the real transfer, and the
  `/api/*` responses carry `no-store`).
- **Automated:** `tests/browser/test_pwa.py` (Playwright) asserts the manifest
  parses without errors, the worker registers and controls the page, and the
  cache holds only whitelisted static assets; `tests/test_pwa_assets.py` checks
  the manifest, icons and worker rules without a browser.
